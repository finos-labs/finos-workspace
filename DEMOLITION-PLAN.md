# Demolition plan: strip the Workspace for donation to FINOS

> **Names.** The research below was written with the product's original names (the product name, its abbreviation, and the tier names). During execution they were all replaced (section 11 lists the new names), and the trial concept was removed (call 21). Where this text describes the trial or the old names, it records what the code used to do.

Started as research from commit `be00e95`; section 8 records what each phase has done.

**Status (2026-10-07): the demolition is done.** What is still open is in [`demolition/final-state.md`](demolition/final-state.md). This plan is the record of what was removed, why, by whose decision, and how it was checked (section 12).
The file lists in [`demolition/`](demolition/) are generated from the code; this document explains them and covers what a list cannot (in-file edits, backend endpoints, configuration).

## 0. Brief

**Purpose.** The code is being stripped and donated to FINOS. Every item is judged by one question: does the donated project need it, and is it free of third-party commercial dependencies, company-hosted services, committed secrets and OpenBB-specific service plumbing? Business logic as such is not the target. What stays is whatever RBAC, authentication, the marketplace, the backend connectors and the agent interfaces need, and RBAC includes the plan, tier, entitlement and seat model (the trial is gone, call 21). **Identity and hosting services stay**: an identity provider, a token mechanism, a hosting target, a storage backend or a deployment path is never removed; only the OpenBB-specific values inside it (hosts, accounts, buckets, registries) become configuration.

**End state**

- Widgets: **Markdown, HTML, iFrame, RSS reader, PDF viewer.** Nothing else, apart from the navigation bar, which is the dashboard's inner-tab switcher rather than a data widget (call 11). Notes and the `newsfeed` list are gone (call 15); the Copilot's notes are Markdown widgets.
- **Protected** (kept and must keep working): **RBAC**, which includes the **plan, tier, entitlement and seat model**; the **auth panel** with password, TOTP and **SSO/OIDC** (Google, Microsoft Entra ID, Okta); **pluggable backend connectors**; the **marketplace** as a pluggable third-party provider, with admin approval of listings that point at externally hosted APIs conforming to the protocol; the **AI/agent interfaces** (custom agents, MCP); dashboards, apps, themes.
- **Identity and hosting services** (kept, OpenBB values become configuration): **cloud file storage** (AWS S3, Azure Blob with Azure identity, the GCP provider, the local folder); the **Platform SDK tokens** (`/sdk/token`, `/sdk/login`); the **deployment and publishing pipelines** (AWS S3/CloudFront/ECR workflows, GHCR publishing, the ECR push script, the image install guides); the **RSS CORS proxy** (a Cloudflare Worker) as a configurable URL.
- Hard-coded company values (mailboxes, hosts, defaults, personal addresses) become **configuration variables** with no OpenBB default (section 7).
- One replacement, as requested: the Mailchimp notification becomes a **pluggable admin-notification hook** (section 6). Nothing else is replaced.
- No backwards compatibility, no transitional states.
- **The Excel integration stays** (`excel-add-in/`, the Excel export dialog, `exceljs`, `VITE_EXCEL_ADD_IN_ENABLED`, the `"excel"` login source) and is scrubbed of the old names like everything else; its mirror of the company's data-platform API is gone (call 22).

The Copilot (the agent interface) is not removed: the chat client, custom agents, MCP, prompts and skills, every `copilot.*` feature flag (web search, Jina reader, SEC filings, documentation links, AI enhancements, the own-key control) and the user's own LLM keys (OpenAI, Perplexity) stay. The Copilot metering stays and is admin-controlled: the per-user daily query limit (`number_copilot_calls_day` on the user, entity and tier entitlements), the `EntitlementUsage` counters, the limit check in `PUT /pro/usage`, the `usage:{uuid}` cache, the midnight reset job and the meter in the chat. Admins of an organization set the limits of its users (`PATCH /admin/entitlement/{user_uuid}`, scoped to the admin's own organization); superusers set them per entity (`PATCH /entity/entitlement/{entity_uuid}`). Tokens are metered next to queries: `number_copilot_tokens_day` is a second daily limit (empty means no limit; columns added by revision `8b1d6f3a7c25`), and the usage counters hold both. Usage is written only by the service that serves the Copilot: `PUT /pro/usage` requires a service token (`sub: metering`, signed with `JWT_SECRET`, created by `python -m scripts.create_metering_token`) in the `X-Metering-Authorization` header, so a user can neither add, subtract nor reset their own usage; admins reset it with `POST /admin/usage/{user_uuid}/reset`. A query is refused once it would pass the query limit or once the day's tokens are used up; tokens are reported after a query has run, so they are always recorded. A limit change takes effect at once because it drops the cached usage, and a user cannot change their own limit (`PATCH /pro/entitlement` is admin-only). Admins also assign the Copilot models and the MCP servers and tools that a role's users may use (`GET`/`PUT /admin/role/{role_uuid}/copilot-access`, tables `role_copilot_model` and `role_mcp_access`, revision `c3a97e5d2b14`, dialog `AdminRoles/RoleCopilotAccessDialog.tsx`). A user whose roles grant nothing of a kind is not restricted in it; once a role grants something, the user may use what their roles grant and nothing else. The service that serves the Copilot checks each request with `POST /pro/copilot/authorize` (metering token), the MCP proxy refuses tool calls that are not granted, and the browser hides what is not granted (`copilot_access` in the `validate-and-sync` payload). `tests/test_copilot_metering.py` and `tests/test_copilot_access.py` are part of the gate. ## 6. The one replacement: admin notification hook

Today the marketplace review request is a Mailchimp email to a hard-coded OpenBB mailbox (`REVIEW_EMAIL = "apps@openbb.co"`, sender `no-reply@openbb.co`, `routers/marketplace_developer.py:37,284-289`), and new-entity creation emails the entity admin (`routers/entity.py:152`). Replace the Mailchimp transport with a vendor-neutral notifier that any administrator can connect to their own notification system.

- **Interface.** New module `api/notifications.py`: an `AdminNotifier` protocol with `async notify(event: str, subject: str, text: str, payload: dict) -> bool`.
- **Built-in transport.** `WebhookNotifier`: HTTP `POST` of `{event, subject, text, payload, occurred_at}` as JSON to the configured URL, optional HMAC-SHA256 signature header, short timeout. No vendor SDK. An administrator points it at Slack, an email gateway, PagerDuty or anything else.
- **Pluggability.** `ADMIN_NOTIFIER` names a class by import path (`package.module:Class`), so a deployment can provide its own transport. Default: the webhook notifier. With nothing configured it logs and does nothing.
- **Configuration.** `ADMIN_NOTIFY_WEBHOOK_URL`, `ADMIN_NOTIFY_WEBHOOK_SECRET`, `ADMIN_NOTIFY_RECIPIENT`, `ADMIN_NOTIFY_SENDER`. The recipient and sender are passed to the transport in the payload; they replace the two hard-coded mailboxes.
- **Events wired.** `marketplace.listing.submitted` (subject and text come from the existing `_format_submission_email`) and `entity.created` (payload carries `admin_email` and the entity name). Every other email call site is deleted, not rerouted.
- **Behaviour.** The submit-for-review endpoint succeeds when no notifier is configured (the listing still shows as pending in the admin marketplace); it returns 502 only when a configured notifier fails, as it does today.
- **Tests.** One test for the webhook transport (payload, signature, failure) and one each for the two events.

### Rules the owner set during the work

These were given while the work was under way. They decide what counts as in scope, and they explain several calls above.

1. **Remove completely, with no backwards compatibility** (2026-10-01). No shims, deprecation periods, fallbacks, placeholders
   for removed things, handling of old persisted data, staging or announcements. Confirmed 2026-10-07 for the old-install
   code: stored-data migrations, persisted-state versions, redirects of renamed routes, deprecated aliases and one-off
   data-repair jobs are deleted. The Copilot service's own forms stay, because that service still sends them.
2. **Plan, tier, entitlement and seat model is RBAC and stays** (2026-10-02). Only the third-party billing, e-mail and sales
   wiring around it goes. The trial was removed on 2026-10-07 ("the admin panel is supposed to provide everything", call 21).
3. **Identity and hosting services stay** (2026-10-02): the cloud storage providers, SSO (Google, Microsoft, Okta), the RSS
   proxy as a configurable URL, the deploy and publishing pipelines, the SDK tokens, and settings such as `FRONTENDURL`.
   Their company-specific values become configuration. The Snowflake Native App is not a hosting target and was removed
   (2026-10-05).
4. **Copilot items stay** (2026-10-02): flags, tools, the user's own model keys, skills. Three exceptions were chosen: the AG Grid
   and AG Charts artifacts, the Snowflake artifacts, and the sandbox data source of the Platform SDK. Metering stays and
   is admin-controlled (2026-10-05): a user can never write or reset their own usage or limit; usage is written only through
   the metering service token; admins set limits and assign Copilot models and MCP servers and tools per role.
5. **The Excel integration stays** (the add-in, its in-app dialogs, `exceljs`). Dead-looking code in it is reported, not deleted.
   On 2026-10-07 its names were purged like everything else and its mirror of the company's data platform was removed
   (call 22).
6. **No vendoring** (2026-10-07). To drop a dependency, write the small amount of code needed on public libraries; never
   copy a package's source, styles or icons into the repository.
7. **The Playwright suite must exist and be usable** (2026-10-07). It is reworked, never deleted, and runs against the stack.
8. **No invented items in documentation or code** (2026-10-07). No example accounts, hosts, companies or default passwords:
   marked blanks in documents; in code, configuration with no default, or a generated seed administrator in a git-ignored
   file. Test fixtures use reserved domains.
9. **"Run the whole thing" means the root `docker-compose.yml`, never Lite** (2026-10-06). The project's old containers, images
   and volumes are deleted outright, not worked around.
10. **A failing test is a question to answer** (2026-10-07), not a constant to report. The MCP server runs on FastMCP 4
    or later (call 23).
11. **Method.** The work is done directly (search, read, edit), findings are shown early, and no orchestration layers or
    background workers stand between the owner and the result. The owner decides what is staged and committed.
