# Turn a dashboard into an app of your backend

This guide builds an app of your backend, which is an entry of its `apps.json`, by arranging a dashboard in the web app and exporting it. You do not have to write the layout by hand: the export records which widgets are on the dashboard, where they sit and how big they are, the values of their parameters, the tabs and the groups. [apps.json](../../reference/schemas/apps-json.mdx) describes the format that you get.

## What you need

You need a backend that is connected to your account, as [Connect a backend](../../features/data-backends/connect-a-backend.md) describes, and a dashboard that holds widgets of that backend. The export covers only the widgets that a backend defines, so take files and iframe widgets off the dashboard first. You also need to be able to edit the backend's `apps.json`.

## Arrange the dashboard

1. Add the widgets to a dashboard and place them as you want the app to open. Give each tab of a dashboard that has several tabs the name that you want to show, which you set in the Navigation Bar widget.
2. Set the parameters of the widgets to the values that the app should start with. The export keeps a value only when it differs from the default in [`widgets.json`](../../reference/schemas/widgets-json.mdx).
3. Link the parameters that belong together, as [Link the parameters of widgets](../../features/widgets/link-the-parameters-of-widgets.md) describes.

## Export the dashboard

1. Right-click the dashboard in the sidebar, or select the three dots that appear next to it, and choose Export apps.json. The item is disabled, with the hint "No backend sources found in this dashboard", when the dashboard has no widget of a backend.
2. In the dialog Export App, fill in the Name and the Description of the app, which are required, and optionally the Image cover, which is the address of a picture. Add the prompts that the Agent should suggest: at most <WebAppValue of="maxAppPrompts" unit="raw" />, each of at most <WebAppValue of="maxAppPromptLength" unit="raw" /> characters.
3. Select Copy to put the app on the clipboard, which gives the message "App copied to clipboard!", or Download App to save it as a file, which gives "App downloaded successfully!". The file has the name of the app in lower case with underscores in place of spaces, and the extension `.json`.

## Put the app in `apps.json`

The export is one JSON object, the description of one app. `apps.json` is an array, so add the object as another element of the array, in the file that your backend serves. A user who connects the backend sees the app after the next refresh, as [Connect a backend](../../features/data-backends/connect-a-backend.md#refresh-edit-or-remove-a-connection) describes.

Check the object before you ship it:

- **Give the app an id that never changes.** Roles name an app by its `templateId`, so add a `templateId`, such as `"sales-overview"`. Without one, FINOS Workspace builds the id from your backend's connection and the app's name, and renaming the app then changes the id.
- **Check the widget ids.** Each layout item names a widget by its key in `widgets.json`, which is what the app needs. When the backend changes a key later, the app leaves that widget out.
- **Check the images.** A relative address in `img`, `img_dark` or `img_light` is resolved against the address of the backend, so the backend can serve the picture itself.
- **Open the app.** Refresh the connection, select the app's card on the Apps page, and check that the dashboard comes out as you arranged it. [Review and debug a backend](review-and-debug-a-backend.md) explains the messages that a backend with a problem gives.

## What the export leaves out

The export has no `selected_agent` and no `mcpServers`, because the dashboard does not know them. Add them to the object by hand when your app needs them. It also marks the app with `"allowCustomization": true`, which lets users change the dashboards that they open from the app. Set it to `false` when those dashboards should stay as you built them, as [apps.json](../../reference/schemas/apps-json.mdx) describes.
