# Semantic properties

Components in the web app do not name colors directly. Instead they read semantic properties, which name a role, such as `--btn-primary-bg` for the background of a primary button. A theme changes the role, and every component that plays it follows. This page lists the semantic properties. It is the page to use when you write a theme stylesheet, because it shows which property to change for the thing that you want to restyle.

Each property is declared on `:root` for the light theme and on `.dark` for the dark theme in `frontend/src/styles/tokens.css`. Its value is usually a `var()` of a [palette](color-palette.mdx) property. The tables are generated from that file and from the frontend source, and each row of a table has three parts:

- The **property** is the custom property's name.
- The **value** shows what the property resolves to in the light theme and in the dark theme, with a swatch for each color. A property that only `:root` declares shows "as light" for the dark theme, and a property that `.force-light` redeclares shows its forced value too.
- The **used** column says how the property reaches the screen. It lists the Tailwind utility classes that read the property, with the most used first. Tailwind maps a utility name to a property in the `@theme` block of `frontend/src/index.css`, so `bg-btn-primary-bg` paints with `--btn-primary-bg`. The column also names the files that use the property most, how many times they use it, and the rules or scripts that read it without a utility.

[Theme scopes and cascade](theme-scopes.mdx) describes how the light and dark values and the cascade work.
