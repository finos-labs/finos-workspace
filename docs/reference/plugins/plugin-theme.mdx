# Plugin theme

A widget plugin draws in a sandboxed frame that shares none of the app's styles. This page describes the few styles that the frame has of its own, and the `theme` trait through which the host tells the plugin about the app's colors.

The frame has three styles of its own. The elements `html`, `body` and `#root` have no margin, they fill the frame, and they hide overflow. The element `<meta name="color-scheme">` is `dark` or `light`, and the frame's `color-scheme` follows the app's theme when it changes. Each file that the manifest's `entry.styles` names is added to the frame as a `style` element.

## The theme trait

The host gives the module a `theme` trait and updates it whenever the theme changes. The trait is an object with these fields:

| Field | Value |
|---|---|
| `mode` | The current mode, which is `"dark"` or `"light"`. |
| `tokens` | An object of color values, keyed by the token names below, together with `font-family`. A color is a six-digit hex value, except a color with transparency, which the host gives as the stylesheet writes it. |
| `locale` | The browser's language, for example `en-US`. |
| `decimals` | The number of decimals to show, which is `2`. |

When the host builds the trait, it reads each token from the computed style of the app's `body`, so a value is the color that the app shows in the current theme. A token that the app does not define is left out of the object. The value of `font-family` is the computed font family of the `body`.

The tokens `brand-main`, `brand-lighter` and `brand-darker` follow `--color-main-100`, `--color-main-50` and `--color-main-200`, as [Brand color, font and text size](../css/brand-font-size.mdx) describes. The host resolves a value that is not hexadecimal to hex before it gives it to the module. That applies, for example, to a `color-mix()` that a theme gives to a brand step, so a stylesheet that changes the brand color changes these tokens too.

Nothing applies the tokens to the plugin's elements, and the frame defines no custom properties of its own. The module reads `theme.tokens` and `theme.mode`, and its own stylesheet decides what to draw. [Style a plugin widget for both themes](../../tutorials/plugins/style-a-plugin-widget.md) shows one way to do that.
