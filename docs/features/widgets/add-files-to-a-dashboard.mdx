# Add files to a dashboard

This guide puts your own documents on a dashboard. Each file becomes a widget that shows the document, and the Agent can read the file when you ask about the dashboard. A file widget is a widget like any other, so you can arrange it, share it and save it in an app.

## What you need

You need an account of type Admin or Developer, because a User cannot upload files and sees no upload area. Your roles may also limit the total size of the files that you upload. When a new upload would exceed that limit, the API refuses it with a message that begins "The upload size limit of" and gives the limit in gigabytes, and an admin can raise the limit on the role, as [Create a role](../administration/create-a-role.md) describes.

FINOS Workspace accepts files with the extensions <WebAppValue of="fileExtensions" />. A file may be at most <WebAppValue of="maxFileBytes" unit="bytes" /> large.

## Add the files

Use whichever of these ways suits you:

- **Drop them on a dashboard.** Drag one or more files from your computer and drop them anywhere on the dashboard. On an empty dashboard the same place is the panel Add your files, which also has a Browse files button that opens your computer's file chooser. Each file also becomes a widget on that dashboard.
- **Use the Widgets Library.** Select Widgets in the sidebar, then Add Data, and then File. The page Create New Widgets from Single or Multiple File takes dropped files or a choice with Browse for file(s), and Continue uploads them. The files then appear in your library, and you add them to a dashboard with Add widgets, like the widgets of a backend.

While the files upload, a message says "Uploading files..." and offers a button that cancels the pending uploads. A message says "Files uploaded successfully" when every file is in, and it points out that you can change the name and the metadata later, either in the widget itself or in the Widgets Library page.

FINOS Workspace sends the files in groups of at most <WebAppValue of="uploadBatchBytes" unit="bytes" />. When you drop more than <WebAppValue of="multipleFilesConfirmationCount" unit="raw" /> files at once, it shows the warning Multiple files detected first and uploads the files only when you confirm.

## What FINOS Workspace makes of a file

Each file becomes one widget in the category Others. The widget's type depends on the extension:

| Extension | Widget |
|---|---|
| `pdf` | A PDF widget, which shows the pages of the document. |
| `html` | An HTML widget, which shows the page. |
| `txt` and `md` | A text widget that shows the content as formatted text. |
| `docx` | The same text widget, which converts the document in your browser. |

The widget's name is the file's name without its extension, and its description is the file's name. When the AI enhancements are on, which is the default, the agent reads the file and proposes a title and a description, so a file named `quarterly-notes.md` can become a widget named "Q3 Regional Deal Notes". When the agent does not answer, the widget keeps the name that comes from the file.

## When a file is refused

FINOS Workspace checks each file before it uploads it and says what is wrong:

- A file with another extension gives "Invalid file(s)" and the message "Only <WebAppValue of="fileExtensionsLabel" plain /> files are supported".
- A file that is too large gives "Invalid file(s)" and the message "File size must be less than 25MB" followed by the file's name.
- A file with the same name as one that you uploaded a moment ago gives "File(s) already uploaded" and lists the names.
- When the upload itself fails, the message says "Error uploading files".

## Find, rename and delete the files

The Widgets Library lists your files on the tab My Data under File Uploads, grouped by kind. Tick one or more files and use the delete button above the list. FINOS Workspace asks you to confirm in the dialog Delete Widget(s), and then it deletes the files and removes their widgets from every dashboard where you used them. A message confirms that the widgets were deleted, or says how many failed and may still appear in your library and your dashboards.

Where the files are kept is up to the deployment, as [Choose where files are stored](../../tutorials/deploy/choose-file-storage.md) describes.
