# Web app configuration

The web app is a static single-page application, so it cannot read environment variables itself. Instead it reads its configuration from a file named `config.js`, which sets `window.__APP_CONFIG__`. The web container renders that file from its environment each time it starts, using `frontend/app-config.js`, which runs inside nginx. During development, `npm run build:runtime` writes the same file from the `VITE_` variables, and `npm run dev` reads those variables directly.

Every setting therefore has two variables. The container variable configures a running container, and the build variable feeds the development tools. A container variable that is not set is left out of `config.js`, and the setting then takes its default from `frontend/src/lib/runtimeConfigSchema.ts`.

A variable that is set is passed on exactly as it is. A string setting may be empty, a boolean variable must be exactly `true` or `false`, and an enum variable must be one of its values. A list variable is comma-separated, and the app trims each item, converts it to lowercase and drops empty items. When a value does not fit its type, `/config.js` and `/healthz` answer with status 500 and an error message that names the variable.

The settings are grouped by the section of `config.js` that they fill. Each table lists the setting, its container variable and build variable, its type and its default. The tables are generated from `app-config.js` and the schema.
