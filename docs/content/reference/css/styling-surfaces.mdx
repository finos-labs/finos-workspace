# Styling surfaces

Workspace draws five kinds of surface, and each takes its styling from a different place. A stylesheet that you write reaches only some of them.

| Surface | Styled by | What you control |
|---|---|---|
| The web app | Tailwind utility classes and the custom properties of `frontend/src/styles/tokens.css` and `frontend/src/index.css` | Every colour, the font and the text scale are custom properties. The base stylesheets are built in. A theme is a stylesheet that `WL_STYLESHEET` names, loaded after them, or a preset that an admin applies in the admin area ([Theme presets](theme-presets.mdx)), so a change needs no rebuild. The other white-label settings cover the name, the logos, the favicon, the description and the keywords. See [Brand colour, font and text size](brand-font-size.mdx) and [Semantic properties](semantic-properties.mdx). |
| HTML widgets | The HTML document that the backend returns, drawn in a sandboxed `iframe` | All of it. The frame inherits nothing from the app, and Workspace adds the `theme` query parameter to the request. See [HTML widgets and artifacts](html-documents.mdx). |
| iframe widgets | The page that the widget embeds | The page's own CSS. Workspace adds `theme` to the request in the same way. |
| Plugin widgets | The plugin's `entry.css`, drawn in a sandboxed frame | All of it. The plugin receives a `theme` trait with the mode and the values of 14 tokens. See [Plugin theme](plugin-theme.mdx). |
| Copilot HTML artifacts | The HTML that the model writes, sanitized and drawn in a sandboxed `iframe`, with one `style` element that Workspace adds | The document's own CSS. The built-in report skill gives the model a stylesheet to use. See [Report classes](report-classes.mdx). |

## What a custom property reaches in the web app

The web app styles colour through Tailwind utility classes such as `bg-btn-primary-bg` and `bg-light-100`. Each colour utility that the Tailwind configuration defines reads a custom property: <Stat of="variableUtilities" /> utilities, used <Stat of="variableUses" /> times in <Stat of="variableFiles" /> files. The palette utilities read the `--color-*` properties of `tokens.css`, so changing a palette step changes every class that names it, and every semantic property that refers to it.

Tailwind's own colours are not properties: `white`, `black` and the named hues such as `red-500`. Components use them <Stat of="builtInUses" /> times in <Stat of="builtInFiles" /> files.

The counts are generated from the frontend source.
