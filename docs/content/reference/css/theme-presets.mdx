# Theme presets

A theme preset is a named set of custom property values that an admin designs on Admin → Theme → Presets ([How to design and apply a theme in the admin area](../../how-to/customize/design-a-theme-in-the-admin-area.md)). The organization keeps its presets, and at most one of them is applied to its users.

## What is stored

The `entity_theme_settings` row of the organization holds the presets in its `settings` document, next to the grouping colours:

| Key | Value |
|---|---|
| `presets` | A list of presets. |
| `active_preset` | The `uuid` of the applied preset, or `null` for the FINOS theme. |

A preset has these fields:

| Field | Value |
|---|---|
| `uuid` | The identifier, a UUID. |
| `name` | 1 to 60 characters after trimming. Unique in the organization without regard to case. |
| `light` | An object of custom property declarations, applied on `:root`. |
| `dark` | An object of custom property declarations, applied on `.dark`. |

A key of `light` or `dark` is a property name, and its value is the CSS value. A rule on `:root` also applies in the dark theme, so a property that `dark` does not hold keeps its `light` value there (see [Theme scopes and cascade](theme-scopes.mdx)).

## What the server accepts

The API refuses anything else with 422.

| Rule | Limit |
|---|---|
| Name of a property | `^--[a-z][a-z0-9-]{0,80}$`. |
| Value | 1 to 200 characters taken from letters, digits, the space and `# % . , ( ) / _ + * " ' -`. The text `url(` is refused in any case. |
| Declarations in `light` or in `dark` | At most 400. |
| Presets in an organization | At most 50. |

## Routes

Every route under `/admin` needs a user of type Admin. The request and response types are on [Workspace API schemas](../http-api/workspace-api-schemas.mdx), and the other routes on [Workspace API](../http-api/workspace-api.mdx).

| Route | What it does |
|---|---|
| `GET /admin/theme-presets` | Returns `presets` and `active_preset`. |
| `PUT /admin/theme-presets/{preset_uuid}` | Creates the preset or replaces it. Answers 409 when another preset has the name. |
| `DELETE /admin/theme-presets/{preset_uuid}` | Deletes the preset, and sets `active_preset` to `null` when it was applied. Answers 404 for an unknown preset. |
| `PUT /admin/theme-presets/active` | Applies the preset named by `{"uuid": ...}`, or the FINOS theme for `null`. Answers 404 for an unknown preset. |
| `PATCH /admin/theme-settings` | Stores the grouping colours. It leaves `presets` and `active_preset` as they are. |
| `GET /app/theme-settings` | Returns the grouping colours and `properties`, the `light` and `dark` declarations of the applied preset, or `null`. Any signed-in user may call it. |

The sign-in response and the dashboard sync carry the same `properties` in their `entity_theme_settings`, so the app applies the theme without a request of its own.

## How the app applies a theme

The app adds two `style` elements to `head`, `style[data-theme="saved"]` and `style[data-theme="preview"]`, each with a `:root` rule and a `.dark` rule. It sets the declarations through the CSS object model, one property at a time, so a value never becomes stylesheet text.

The layers come in this order, and a later one wins at equal specificity:

1. The base stylesheets, `tokens.css` and `index.css`.
2. The theme stylesheet that `WL_STYLESHEET` names.
3. `style[data-theme="saved"]`: the applied preset. It is filled when the app loads and signs in, and again after an admin applies or changes a preset.
4. `style[data-theme="preview"]`: the values in the editor. It holds values only while the Presets tab is open. While it holds values the saved layer is empty, so a preset that you choose in the editor stands alone and does not inherit from the applied one.

The sign-in page loads before any organization is known, so it shows layers 1 and 2 only.

## What the editor lists

The editor lists every custom property that `tokens.css` and `index.css` declare on `:root` or `.dark`, except `--text-scale`, which the font size setting drives.

| Group | Properties |
|---|---|
| Brand | The `--color-main-*` steps, `--font-family` and `--radius`. |
| Palette: _ramp_ | The steps of one ramp of the [colour palette](colour-palette.mdx). |
| One group for each prefix | The [semantic properties](semantic-properties.mdx), for example `btn` or `tab`. |
| Base | The [base properties](base-properties.mdx) of `index.css`. |

In the dark mode the editor shows a property's value as the dark theme gets it: the preset's `dark` value, else its `light` value, else the dark declaration of the base stylesheets, else the light one.
