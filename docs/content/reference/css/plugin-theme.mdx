# Plugin theme

A widget plugin draws in a sandboxed frame that shares none of the app's styles. The frame has these styles of its own:

- `html`, `body` and `#root` have no margin, fill the frame, and hide overflow.
- `<meta name="color-scheme">` is `dark` or `light`, and the frame's `color-scheme` follows the app's theme when it changes.
- Each file that the manifest's `entry.styles` names is added as a `style` element.

## The theme trait

The host gives the module a `theme` trait and updates it when the theme changes. Its fields are:

| Field | Value |
|---|---|
| `mode` | `"dark"` or `"light"`. |
| `tokens` | An object of colour values, keyed by the names below, and `font-family`. A colour is a six-digit hex value, except one with transparency, which is given as the stylesheet writes it. |
| `locale` | The browser's language, for example `en-US`. |
| `decimals` | The number of decimals to show, `2`. |

The host reads each token from the computed style of the app's `body` when it builds the trait, so a value is the colour that the app shows in the current theme. A token that the app does not define is left out. `font-family` is the computed font family of the `body`.

`brand-main`, `brand-lighter` and `brand-darker` follow `--color-main-100`, `--color-main-50` and `--color-main-200` (see [Brand colour, font and text size](brand-font-size.mdx)). The host resolves a value that is not hex, such as a `color-mix()` that a theme gives a brand step, to hex before it gives it to the module, so a stylesheet that changes the brand colour changes these tokens too.

Nothing applies the tokens to the plugin's elements, and the frame defines no custom properties: the module reads `theme.tokens` and `theme.mode`, and its own stylesheet decides what to draw.
